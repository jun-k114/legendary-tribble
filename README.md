# 請求・入金管理の体制

請求書の **発行漏れ・送付漏れ・入金確認漏れ・記入漏れ** を、個人の注意力ではなく仕組みで防ぐための管理表と運用ルールです。

- 管理表: [`請求入金管理表.xlsx`](請求入金管理表.xlsx)
- 管理表の生成スクリプト: [`tools/build_workbook.py`](tools/build_workbook.py)(列や選択肢を変える場合はこれを修正して再生成)

---

## 1. 今の入出金確認表で漏れが起きる理由と対策

| 起きがちな漏れ | 原因 | この管理表での対策 |
|---|---|---|
| 請求書を出し忘れる | 請求書を作った後に表へ記入するため、作らなければ表にも残らない | **台帳に先に登録して請求番号を取る**運用に変更。毎月請求の取引先は、当月の請求がないと「請求漏れ候補」を表示。月次で受注・納品一覧と突合 |
| 作ったが送っていない | 送付の記録欄がない/任意 | 送付日が空欄の間はステータスが **「未送付」** のまま残る |
| 記入漏れ | 必須項目が決まっていない | 必須項目が空欄だと **「要入力」** と「入力漏れ」列に項目名を表示 |
| 入金確認漏れ | 入金を探しに行く運用(請求→通帳)だと、見落とした入金に気付けない | **通帳の入金を全件「入金明細」に転記**し、請求番号で消込。消込できない入金は「未消込」で残る |
| 期日を過ぎても気付かない | 期日を手で計算・記入していない | 取引先マスタの支払条件から **入金期日を自動計算**。過ぎると「期日超過」+超過日数 |
| 金額の不一致に気付かない | 請求額と入金額の差を計算していない | 未回収残高を自動計算。一部入金・過入金を判定。手数料差引は専用欄 |
| 表と会計の数字がずれる | 突合していない | 月次で **台帳の未回収残高 = 会計ソフトの売掛金残高** を照合(差額を自動表示) |
| 誰が確認したか分からない | 確認記録がない | 入金済の請求に「消込確認者」必須。月次チェック記録に実施者・承認者を記録 |

## 2. 役割分担(ダブルチェックの体制)

少人数でも、**「入力する人」と「確認する人」を分ける**ことが漏れ防止の基本です。

| 役割 | 担当業務 | 例 |
|---|---|---|
| 請求担当 | 請求台帳への登録、請求書作成・送付、送付日の記入 | 事務担当A |
| 入金担当 | 通帳・ネットバンキングの入金を入金明細へ転記、消込 | 事務担当B(請求担当と別が望ましい) |
| 営業担当 | 期日超過先への確認・督促、受注・納品情報の提供 | 取引先マスタの「営業担当」 |
| 確認者/責任者 | 消込の確認(消込確認者)、月次チェックの承認 | 経理責任者・管理者 |

> 1人で運用せざるを得ない場合も、**月次チェックの承認だけは別の人(代表者など)** が行ってください。

## 3. 業務の流れとタイミング

### 請求のたびに
1. 請求書を作る**前に**「請求台帳」に1行追加(請求日・取引先コード・件名・税抜金額・税率・送付方法)
2. 自動採番された **請求番号を請求書に記載**して作成
3. 送付したら **送付日・送付者** を入力(ここまでで「入金待ち」になる)
4. 誤りがあった請求は行を消さずに「取消」を選び、備考に理由。正しい請求は新しい行で再発行

### 入金があったら(毎日〜少なくとも週2回)
1. 通帳・ネットバンキングの入金を **請求に関係ないものも含め全件**「入金明細」に転記
2. 振込名義・金額から該当する請求番号を「消込先請求番号」に入力
   - 1回の入金で複数請求分 → 行を分けて金額を按分
   - 振込手数料が差し引かれた → 請求台帳の「手数料・値引等」に差額を入力
3. 請求台帳で残高0(入金済)になった請求を確認者が確認し「消込確認者」に記名

### 毎週(例: 月曜)
- 「チェック」シートを開き、**要入力・未送付・未消込** を解消
- **期日超過** の一覧を営業担当へ連絡し、先方へ確認。結果を請求台帳の備考に記録

### 毎月(締め後、例: 翌月5営業日以内)
「チェック」シートの対象月を設定し、次を確認して「月次チェック記録」に記入:

1. 契約・受注・納品・作業報告の一覧と、対象月の請求台帳を突合(**請求漏れ**の確認)
2. 未送付 0件
3. 要入力 0件
4. 未消込入金・番号誤り 0件
5. 期日超過の全件について督促・状況確認済
6. 会計ソフトの売掛金残高と台帳の未回収残高の差額 0
7. 毎月請求先の請求漏れ候補 0件

→ 実施者が記入後、**責任者が承認**(承認日の空欄が残る月はオレンジ表示)

## 4. 管理表の構成

| シート | 内容 |
|---|---|
| はじめに | 使い方・ステータスの意味・ルール |
| チェック | 要対応の件数・金額の一覧、会計ソフトとの残高照合、総合判定 |
| 請求台帳 | 請求書1枚=1行。請求番号の自動採番、入金期日・残高・ステータス・入力漏れの自動判定 |
| 入金明細 | 通帳の入金を全件転記し消込。消込状態(消込済/未消込/番号誤り)を自動判定 |
| 取引先別残高 | 取引先ごとの未回収残高、超過日数別(1〜30/31〜60/61日以上)、請求漏れ候補 |
| 取引先マスタ | 取引先コード、振込名義、支払サイト・支払日、毎月請求の有無、営業担当 |
| 月次チェック記録 | 月次チェックの実施・承認の記録(36か月分) |
| 設定 | 請求番号の接頭辞、基準日、期日間近の日数、プルダウンの選択肢 |

- **黄色のセル=入力**、灰色のセル=自動計算(シート保護で上書き防止。パスワードなし)
- 並べ替えは不可(請求番号が行位置で採番されるため)。絞り込みはフィルタを使用
- サンプルデータ(備考に `SAMPLE` / `サンプル`)は運用開始前に消去

### 請求台帳のステータス

| ステータス | 意味 | 対応 |
|---|---|---|
| 要入力 | 必須項目の漏れ等 | 「入力漏れ」列の項目を入力 |
| 未送付 | 送付日が空欄 | 送付して送付日・送付者を入力 |
| 入金待ち / 期日間近 | 送付済・期日前 | ― / 必要に応じリマインド |
| 一部入金 | 入金額が不足 | 差額の理由を確認(手数料なら手数料欄へ) |
| 期日超過 / 一部入金・超過 | 期日を過ぎて残高あり | 督促・状況確認 |
| 過入金 | 入金が多い | 二重振込・消込誤りを確認 |
| 入金済 | 残高0 | ― |
| 取消 | 無効にした請求 | ― |

## 5. 今の入出金確認表からの移行手順

1. 「取引先マスタ」に取引先を登録(支払サイト・支払日・毎月請求の有無)
2. 「設定」の請求番号の接頭辞・入金口座を自社用に変更
3. 現在 **未入金の請求** を請求台帳に登録(送付日も入力)。入金済みの過去分は移行不要
4. 以降の請求はすべて台帳で採番
5. 移行月の月末に、会計ソフトの売掛金残高とチェックシートの未回収残高が一致することを確認

## 6. 管理表を変更したい場合

`tools/build_workbook.py` を修正して再生成します(Python 3 + openpyxl)。

```bash
pip install openpyxl
python tools/build_workbook.py 請求入金管理表.xlsx
```

※ 再生成すると入力データのない新しいファイルになります。運用中のファイルは上書きしないでください。
